FOR SCRIPTS, AGENTS & CURIOUS MINDS

Small API. Private delivery.

Encrypt on your own machine, store ciphertext for a little while, and build the sharing link yourself. No account, API key, or server-side encryption step.

Agent instructions: /llms.txt ↗

Start with the Node.js client

Requires Node.js 22 or later. Uses built-in Web Crypto and fetch, with no npm dependencies. Download both files into the same directory and review them before running.

BASE=https://happysecret.happysecret-renedotdev.workers.dev
curl -fsS "$BASE/happysecret.mjs" -o happysecret.mjs
curl -fsS "$BASE/crypto.js" -o crypto.js

# Reads plaintext locally. Only ciphertext is uploaded.
node happysecret.mjs create --expires 1h --views 1 < secret.txt

# Prints a link: https://…/s/<id>#<key>
# To retrieve in a terminal (uses one view):
node happysecret.mjs get 'https://…/s/<id>#<key>'

Use --server https://your-host or HAPPYSECRET_URL for a self-hosted instance. Secrets are read from stdin so they do not need to appear in command arguments or shell history.

HTTP endpoints

MethodPathBehavior
PUT/api/v1/secrets/{id}Create an encrypted secret
POST/api/v1/secrets/{id}/consumeReturn ciphertext and consume one view
GET/s/{id}Open reveal page; consumes no view

The ID is 32 random bytes encoded as 64 lowercase hexadecimal characters, generated on your machine. A successful creation returns HTTP 201 with {id, path, expiresAt, maxViews}. Construct the complete link locally: origin + path + "#" + base64url(key).

Encrypted envelope, version 1

{
  "v": 1,
  "algorithm": "aes-256-gcm",
  "nonce": "<standard base64 of 12 random bytes>",
  "ciphertext": "<standard base64 of ciphertext + 16-byte tag>",
  "expiresAt": "2030-01-01T12:00:00.000Z",
  "maxViews": 1
}

The timestamp above illustrates the format: use an actual future timestamp within the next 7 days. Canonical UTC ISO format with milliseconds is required. maxViews defaults to 1 when omitted. Every other field is required. Extra fields are rejected.

  1. Generate a fresh random 32-byte AES key, a fresh 12-byte nonce, and a random 32-byte ID for every secret.
  2. Use UTF-8 plaintext, AES-256-GCM, and a 128-bit authentication tag. Do not reuse keys/nonces.
  3. Authenticate this exact UTF-8 additional data, with no newline:
    happysecret:v1:{id}:{expiresAt}:{maxViews}
    The final value is an integer in decimal, using 1 if omitted.
  4. Append the 16-byte tag to the ciphertext and encode in standard padded base64. Encode the nonce in standard base64.
  5. Upload the envelope. Keep the key out of the request, request headers, and logs.
  6. Encode the key as unpadded base64url (43 characters) and append it after # in the sharing link.

Python clients can use cryptography.hazmat.primitives.ciphers.aead.AESGCM; encrypt(nonce, plaintext, aad) already appends the authentication tag. The Python documentation describes the interface. openssl enc does not support GCM.

Retrieve deliberately

A successful consume request returns HTTP 200 with the encrypted envelope and remainingViews. Decrypt locally using the key from the link and the same additional authenticated data. The view is consumed when ciphertext is released, even if decryption fails or the response is lost. Retrying a consume request can use another view. GET, HEAD, link previews, and simply opening the page never consume a view.

Limits & errors

Limits
32 KiB of UTF-8 plaintext; 64 KiB maximum JSON request; 1–100 views; expiration within 7 days. Creation is rate limited to 30 attempts per IP per minute at each Cloudflare location.
400 Bad Request
Invalid envelope, size, views, timestamp, or JSON.
403 Forbidden
Cross-origin browser requests are blocked. CLI requests do not need an Origin header.
405 Method Not Allowed
Use PUT for creation and POST on /consume for retrieval.
409 Conflict
ID already used. Generate a fresh random ID; do not overwrite existing secrets. The ID is reserved until at least 7 days after the original expiry.
410 Gone
Missing, expired, or fully consumed. The response does not distinguish these cases.
429 Too Many Requests
Wait at least a minute before attempting creation again.

Trust & deployment

This is a public test deployment. The API stores encrypted content and expiration/view metadata. It cannot validate that a client used encryption correctly, and the service operator still controls the delivered browser code. The full link is a bearer secret: anyone holding it can retrieve and decrypt. Read how privacy works.

Source, protocol, and deployment configuration are public on GitHub. Agent discovery is available at both /llms.txt and /llm.txt.
