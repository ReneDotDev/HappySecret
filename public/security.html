A CLEARER LOOK AT THE PROMISE

Your secret. Your key.

HappySecret helps you share a small piece of text for a limited time. Here is what the application does, and where its guarantees end.

Encryption happens on your device

The browser uses its native Web Crypto API to encrypt text with AES-256-GCM, a fresh random 256-bit key, and a fresh 96-bit nonce. Authentication covers the ciphertext, its ID, expiration, and original view limit. Plaintext and the key are not included in the upload.

The complete link is the credential

A sharing link looks like /s/<random-id>#<key>. Browsers do not send the fragment after # in HTTP requests. The page reads it locally to decrypt. Anyone who receives the complete link can use it, so share it through a channel you trust. Messaging services, browser extensions, clipboard managers, and devices handling the complete link may be able to read it.

A view is a release of ciphertext

Loading a link does not consume it. Clicking “Reveal the secret” makes an explicit POST request that atomically reduces the view count. The final view removes ciphertext from active storage. Failed decryption or an interrupted response still uses a view if the server released the ciphertext. Recipients can save, copy, photograph, or forward what they receive.

Expiration & storage

Encrypted content is stored in Cloudflare Durable Object storage with an expiration of at most 7 days. Expired secrets become inaccessible immediately based on the timestamp. An alarm schedules deletion from active storage. A small ID-collision marker remains for 7 days after expiration and is then deleted. Deletion from active storage is not a promise of immediate physical erasure from Cloudflare’s underlying backups or recovery systems.

What the server can see

The service receives ciphertext, nonce, ID, expiry, view limit, and normal network request information. Cloudflare handles traffic and may process connection metadata. Application request logging and Workers observability are disabled in this deployment. There are no third-party scripts, fonts, analytics, ads, or tracking cookies in the application.

Open source & remaining trust

The application source and deployment configuration are open source under the MIT license. Source review helps explain the design; it does not independently prove what code a deployment serves. A compromised site or device could capture plaintext or keys. For a smaller trust boundary, review and run the command-line client locally, or self-host the service.

This is an initial public test deployment, without an independent security audit. Use test values while evaluating it.
